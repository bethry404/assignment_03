What I learned:
This assignment taught me how Streamlit apps work across reruns. A widget like st.text_input or st.file_uploader returns a value, and that value can be empty or None on the first run, so I needed a guard before processing. I also learned that uploaded files are bytes, so they must be decoded into text before splitting lines and skipping blank entries. In the final app, I learned that values that must survive a rerun belong in st.session_state, and they must be initialised once before being updated on a button-triggered rerun.

What was challenging:
The hardest part was the session-state pattern in the multi-file app. An ordinary variable resets on every rerun, so the counts and summary history would not accumulate correctly. I also had to be careful that the uploader kept the same file across reruns, so processing only happened when the button was clicked instead of whenever a file was present.

What I will practice next:
I want to keep practicing the same workflow: initialise state, read the widget’s return value, guard the work, update state, then display results with st.metric or st.info. I also want to build more apps that handle uploaded files, decode bytes to text, and use session state so I get more comfortable with stateful Streamlit design.
