This assignment helped me understand how Streamlit apps behave as interactive programs rather than simple scripts. One of the biggest things I learned was that a script reruns from the top every time the user does anything, including typing into a widget, choosing a file, or clicking a button. That meant I had to think carefully about where to put my guard conditions so the app only processed input when there was actual data to work with. In the first app, I learned how the text input widget returns a value, and that when the page first loads it is an empty string, so the code needed an if package_data guard to avoid trying to parse nothing.

I also learned how file uploads are different from plain text: the uploaded file comes in as bytes, not text, so I had to decode it before splitting it into lines. This was an important concept because a text file often ends with a newline, which creates an empty final line. I had to skip blank lines to prevent parse_packaging from raising a ValueError. In the second app, I saw that the file uploader returns None until a file is chosen, so it also needed a guard to avoid processing before an upload.

The biggest challenge for me was the third app, because it required me to use session state correctly. I had to initialise the values once, update them on the button-triggered rerun, and then display those values using st.metric. I also had to remember that an ordinary variable like files_processed = 0 resets on every rerun, so it cannot be used for anything that has to survive across interactions. The solution was to put the counts and summary history into st.session_state and only update them when the button click caused the rerun. That was the most important concept in the assignment because it taught me how stateful web apps work.

I also struggled at first with understanding the difference between a widget’s return value and what the page shows. For example, the uploader keeps the file chosen even after reruns, so processing must happen only on a button click instead of whenever a file is present. This taught me to be careful about event-driven logic and not to assume that uploading a file means the app should process it immediately.

In the future, I want to keep improving my understanding of the rerun model and state management in Streamlit. I can do this by building more apps with input widgets, guards, buttons, and session state so I become more comfortable with the lifecycle of a Streamlit page. I also want to practice handling uploaded data more deliberately, especially converting bytes to text, decoding correctly, and cleaning inputs before using them. Finally, I want to make my code more intentional by planning the flow first: initialise state, read widget values, guard the work, update state, then display results. That will help me build apps that are more reliable and easier to debug.
